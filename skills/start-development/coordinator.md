# Native coordinator action contract (v2)

This is executed by the real Sonnet parent/coordinator with Bash/Read/Edit/Write. The JS Workflow has no filesystem API. Read the `AUTODEV_REQUEST` object and preserve every CLI error. Parent supplies the run lease before launch. `run_id/attempt_id` in this request identify that lease; selected backlog `execution.attempt_id` can differ and binds task reviews/model logs.

Before any write, `operation.mjs --action start --run RUN --attempt ROOT_ATTEMPT --task TASK --id REQUEST_OPERATION_ID --stage STAGE --target TARGET`. STARTED permits the action; ALREADY_APPLIED returns the saved result after inspecting current files; OBSERVE_REQUIRED forbids blindly applying edits. Complete with `--action complete --result JSON_FILE`. `inspect` is a read and does not create a writer receipt. An interrupted receipt is preserved; after actual diff inspection use `operation --action observe` with JSON containing `observed_fingerprint` and `reason`. Never use a new ID just to bypass an unfinished writer.

| action | Required concrete work |
| --- | --- |
| inspect | Run `context.mjs` and `next.mjs --run RUN`. Return snapshot from actual files: `architecture_ready`, `tasks` (including `execution`), `observation_id`, `completed_since_audit` from progress.json, and structured `resume` from next. Architecture is ready only with full original-requirement mapping and valid contract, not a placeholder file. Return WAIT/BLOCKED honestly. Derive `repair_attempt` (zero-based) from saved implementation receipts when resuming later repair rounds. |
| checkpoint-architecture | Validate all task/check coverage with context.mjs and preserve Opus long plan; transition ARCHITECTURE→PLAN. |
| plan | Select dependency-ready task with task.mjs --action select; preserve its execution on resume. Write short sprint contract. If payload.resume exists, inspect/reconcile that exact operation, preserve partial product, enter REVIEW/VERIFY rather than IMPLEMENT. Return snapshot with the selected execution. |
| diagnose | Inspect repeated failures and logs, write a different root-cause hypothesis and repair strategy. Preserve every failed check. |
| persist-review / persist-final-review / persist-final-audit | Independently returned assessment must include v2 `status`, snapshot `product/contract/identity/session/run/task/attempt`, `task_ids`, `executions`, original requirement refs and actual findings. Collect/import the actual runtime observation, then use assessment.mjs to save verbatim. It refuses stale snapshots and mismatched version/kind/scope. A successful save is coordinator PASS even when the assessment itself is NEEDS_FIX; the Workflow evaluates that decision separately. Missing runtime proof remains UNVERIFIED. Set `snapshot.blocker_scope="global"` only for a global outage; task-specific evidence failure can defer that task and continue independent work. |
| close-task | Execute task.mjs --action complete. Return PASS only if its actual task gate passes; never set backlog PASS by hand. Review scope/task execution and all acceptance reports must be current. Return snapshot including persisted progress. |
| checkpoint-audit | Save real Opus milestone assessment, then run progress.mjs to reset completed_since_audit only after a valid PASS/NEEDS_FIX audit. This maintains cadence across repeated one-sprint bursts. |
| replan-milestone / replan-final-review / replan-final-audit | Apply concrete independent findings to the long/short plan; use task.mjs --action reset on affected tasks. Preserve the original mission. Reset creates a fresh execution ID, invalidating old task approvals even if source returns to identical bytes. |
| replan-final-verification | Read actual failed check IDs/reports, map to tasks and reset them with task.mjs. Return PLAN and continue implementation. Missing environment evidence is not a code repair; record exact blockers instead of repeating the same final check forever. |
| defer-or-replan | Preserve task blocker/failure and Opus recommendations. If unresolved, mark just this task BLOCKED with task.mjs and continue dependency-ready independent tasks. Revisit it only with a new hypothesis or changed external evidence. Do not remove it from scope. |
| prepare-final-gate | Confirm current task/check/requirement coverage and final assessments, all current execution IDs, all operation results. If verification changed product/contract after final assessment, require a fresh review/audit. Transition through AUDIT→IDLE while owner remains active. Parent must wait for actual Workflow completion, save SDK terminal+drained proof, `state end`, then execute independent verify. Never call this COMPLETE. |

Every result is JSON with `status`, `summary`, `findings`, and optional `snapshot`. Preserve the actual independent result in payload; a status with zero findings still matters. Resolved findings can remain in history with `resolved:true`; unresolved major/critical findings forbid PASS.

`/goal` is the outer continuation mechanism. On CONTINUE_PARENT, read current context again, update Workflow `observation_id` to the actual observation hash, and relaunch the same mission. Stable implementation receipt IDs use task/execution/repair-round; fresh inspector prompts use observation_id so runtime cached responses cannot masquerade as current filesystem observations. Never reuse a stale observation_id after external edits/recovery.
