# Native coordinator action contract (v2)

This is executed by the real Sonnet parent/coordinator with Bash/Read/Edit/Write. The JS Workflow has no filesystem API. Read the `AUTODEV_REQUEST` object and preserve every CLI error. Parent supplies the run lease before launch. `run_id/attempt_id` in this request identify that lease; selected backlog `execution.attempt_id` can differ and binds task reviews/model logs.

Before any write, `operation.mjs --action start --run RUN --attempt ROOT_ATTEMPT --task TASK --id REQUEST_OPERATION_ID --stage STAGE --target TARGET`. STARTED permits the action; ALREADY_APPLIED returns the saved result after inspecting current files; OBSERVE_REQUIRED forbids blindly applying edits. Complete with `--action complete --result JSON_FILE`. `inspect` is a read and does not create a writer receipt. An interrupted receipt is preserved; after actual diff inspection use `operation --action observe` with JSON containing `observed_fingerprint` and `reason`. Never use a new ID just to bypass an unfinished writer.

Every result is JSON with `status`, `summary`, `findings`, and optional `snapshot`. Finding severity: major/critical only for a defect that makes this very action unsafe or wrong, because an unresolved major/critical blocks PASS; work a later stage has not done yet (independent review, verification, other tasks, milestone audit) is minor. Preserve the actual independent result in payload; a status with zero findings still matters. Resolved findings can remain in history with `resolved:true`; unresolved major/critical findings forbid PASS.

`/goal` is the outer continuation mechanism. On CONTINUE_PARENT, read current context again, update Workflow `observation_id` to the actual observation hash, and relaunch the same mission. Stable implementation receipt IDs use task/execution/repair-round; fresh inspector prompts use observation_id so runtime cached responses cannot masquerade as current filesystem observations. Never reuse a stale observation_id after external edits/recovery.

## Bounded handoff and long-running recovery

`failure.json` is an optional additive v2 causal journal. Old missions start with no events; prior evidence is never promoted to PASS by migration. Failure history is mission/task scoped and retains execution/run/session IDs across owner/session changes. `failure_state` returns two recent events, the latest strategy, cause, next experiment and requested next model; do not reread every old log at every sprint. Relevant test selection belongs to the sprint contract; final verification still refreshes every mandatory check.

After two code-repair failures, use Sonnet diagnosis and implementation. After four, use Opus to change the technical hypothesis or defer this task. An explicit design contradiction returns to Opus immediately. Environment/quota/permission failures remain in total history but do not consume code-repair escalation rounds. A genuinely new Opus strategy opens another elevated repair window; it does not erase failures or shrink the mission. Missing runtime capability is not a failed code experiment. If every independent task is externally blocked, save exact recovery instructions and let the parent report BLOCKED; `/goal` cannot create model access, approve permissions or start a new cloud session by itself.

On forced termination before a failure result was saved, the parent must first obtain genuine terminal+drained proof, reconcile partial edits, and record the interruption as category `terminated` with the actual next diagnostic step. Never treat an absent result as a successful call. Reopen blocked work only after a new causal strategy or changed external evidence is observed.

A read-only review/audit is always preceded by a fresh coordinator inspection in the Workflow. Return the actual full context (product/contract/identity, mission/session/run/task/attempt, selected executions and requirement refs); never reuse a plan snapshot after implementation. The deterministic inspection sequence identifies distinct reads, not acceptance evidence. If initial planning was interrupted before contract publication, the parent finishes the native burst and recovers the root, then uses repair-plan.mjs with terminal proof; retain and read the archived draft. Do not reset a published plan as an initial draft. Backlog task ID mission is reserved for the parent root; preserve requirement IDs via requirement_refs.

Readonly interruption is a separate continuation basis: native reviewers have no writer receipt. When next returns recovery_kind=READONLY, inspect retained product, frozen stopped-root state/proof/raw and any completed implementation receipt. Do not call operation.observe on a completed or absent receipt. Select with `--resume true --observed_fingerprint ACTUAL_CURRENT_HASH --reason ACTUAL_INSPECTION_REASON`; this preserves task execution and restarts REVIEW/VERIFY, with changed code returning to REVIEW. An INTERRUPTED writer still uses operation.observe. Each completed/reset task clears its own continuation. Finish overdue persisted milestone audits before the next task; checkpoint-audit must return persisted completed_since_audit=0 or stop as UNVERIFIED instead of repeatedly spending Opus calls.
